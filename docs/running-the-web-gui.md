# 运行 Web GUI：一份写给非科班同学的详细说明

> 目标：读完你能自己把 loca 的网页界面跑起来、用起来、关干净，遇到问题能自己排查。
> 全文的命令我都在这台机器上实测过，贴出来的输出是真的。

---

## 一、先花三分钟搞懂"到底发生了什么"

不懂网络也能用，但知道这几个词你会踏实很多。

### 1. 三个概念

| 词 | 通俗解释 | 在我们这里是谁 |
|---|---|---|
| **服务端 / server** | 一个跑在你电脑上、一直"守着"等人的程序 | `loca serve` 启动的那个 Python 进程 |
| **客户端 / client** | 主动去"找"服务端说话的东西 | 你的浏览器 |
| **端口 / port** | 一台电脑上同时跑着很多程序，端口就是门牌号，用来区分找谁 | `8765`，我们给 loca 挑的门牌号 |
| **127.0.0.1 / localhost** | "本机"的意思，不是外网地址，只有你自己这台电脑能连 | 我们绑定的地址 |

**打个比方**：`loca serve` 相当于在你家客厅开了个小窗口，窗口门牌是 `8765`，而且这个窗口**只朝屋里开**（`127.0.0.1`），外面街上的人看不见。浏览器就是你自己走到窗口前面点单。

### 2. 你发一条消息，背后发生了什么

```
① 你在浏览器输入框打字，回车
        ↓
② 浏览器把这句话 POST 到 127.0.0.1:8765/api/chat
        ↓
③ 服务端拿到话，启动 agent 循环：
     调 DeepSeek → 模型说要写文件 → 先给原文件存一份快照 → 执行 write_file → 结果回灌 → 再调模型 …
        ↓
④ 中间每产生一小段文字/一次工具调用，服务端就立刻推一条给浏览器
        ↓
⑤ 浏览器收到一条渲染一条，所以你看到文字是一个一个蹦出来的
```

第 ④ 步用的技术叫 **SSE（Server-Sent Events）**，你可以理解成"服务器主动往浏览器一条条推消息"。这也是为什么它不像普通网页那样"转半天圈然后一次性显示"——它是一边生成一边给你。

### 3. 安全性：为什么默认绑 127.0.0.1

因为 loca 的 `shell` 工具**能执行任意 shell 命令**。如果绑成 `0.0.0.0`（监听所有网卡），同一个 WiFi 下的任何人访问你的 IP 就能操纵你电脑上的命令行——这等于把家门钥匙插在门上。

所以：**别改 `--host`**，保持默认的 `127.0.0.1`。

## 二、启动方式 A：VS Code（推荐）

你以 VS Code 为基准，所以走这条路最省事。

### 步骤

1. VS Code 打开项目文件夹 `D:\Projects\loca`
   （`文件` → `打开文件夹`，或者直接把文件夹拖进 VS Code 窗口）

2. 按 **`Ctrl + Shift + D`** 打开左侧的 **运行和调试** 面板

3. 顶部下拉框里选 **`loca serve (Web GUI)`**

4. 按 **`F5`**（或点绿色的 ▶ 三角）

5. 集成终端会弹出并打印日志，**几秒后浏览器自动打开** loca 的聊天页面

### 启动成功的标志

终端里出现这四行，就说明服务起来了：

```
INFO:     Started server process [19748]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8765 (Press CTRL+C to quit)
```

- 第 2、3 行表示"程序初始化完了"。
- 第 4 行是重点：`Uvicorn running on http://127.0.0.1:8765` = "窗口开好了，门牌 8765"。

> **浏览器没自动打开？** 不是出错。手动在地址栏输 `http://127.0.0.1:8765` 回车即可。
> 自动打开是 `launch.json` 里的 `serverReadyAction` 配置做的，它靠匹配日志里那行 `Uvicorn running on ...` 来触发，偶尔会慢半拍或没接上。

> **想让这个窗口一直开着**：不要关终端。终端一关，进程就死了，窗口也就没了。

## 三、启动方式 B：终端

如果不想用 VS Code 的调试面板，也可以直接在终端跑。

1. 在 VS Code 里按 **`` Ctrl + ` ``**（反引号，Esc 下面那个键）打开集成终端
2. 敲这一行回车：

```
.venv\Scripts\python.exe -m loca.cli serve
```

### 为什么写这么长，不直接敲 `loca serve`？

因为 `loca` 这个命令的快捷方式（`loca.exe`）装在项目的 `.venv\Scripts\` 里。**虚拟环境没激活的时候，系统不知道去哪找它**，你就会看到"不是内部或外部命令"。

两个办法绕过：

- **办法 1（上面用的）**：写完整路径，`-m loca.cli` 的意思是"把 loca 包里的 cli 模块当程序跑"。永远有效，不用管环境激活没激活。
- **办法 2**：先激活虚拟环境，之后就能用短命令了

  ```
  .venv\Scripts\activate
  loca serve
  ```

  激活成功的标志是命令行前面多出 `(.venv)`。用完可以敲 `deactivate` 退出。

## 四、确认它真的活着

有三种办法，从简单到"技术一点"：

### 办法 1：看页面

浏览器打开 `http://127.0.0.1:8765`，能看到深色聊天界面就对了。

### 办法 2：看终端日志

每来一个请求，终端会多打印一行。比如你刷新一次页面，会看到：

```
INFO:     127.0.0.1:55538 - "GET / HTTP/1.1" 200 OK
```

这行怎么读：`127.0.0.1:55538` 是**浏览器的**临时端口（每次刷新都变，正常），`GET /` 是"请求了首页"，`200 OK` 是"成功了"。

### 办法 3：访问体检接口

浏览器打开 `http://127.0.0.1:8765/api/health`，会看到一段 JSON：

```json
{
  "status": "ok",
  "default_workspace": "D:\\Projects\\loca",
  "providers_with_keys": ["deepseek"]
}
```

三个字段的含义：

| 字段 | 含义 | 需要注意什么 |
|---|---|---|
| `status` | 服务状态 | 是 `ok` 就行 |
| `default_workspace` | 页面顶栏工作区输入框的**初始值** | 默认是项目根目录。它只是默认值 —— 页面上可以随时改成别的已存在目录 |
| `providers_with_keys` | 哪些 provider 读到了 API key | **必须是 `["deepseek"]`**。如果是空数组 `[]`，说明 `.env` 里的 key 没被读到，聊天会报错 |

## 五、开始用

1. 页面底部有输入框，打字后 **回车** 发送（部分浏览器是 `Ctrl+Enter`，界面上有提示）
2. 你会看到三类气泡：
   - **左边的回答**：模型流式吐出的文字
   - **工具调用卡**：显示 `→ read_file(path='README.md')` 和结果 `✓ read_file`，绿色对勾=成功，红色叉=失败
   - **红色错误条**：出问题时出现（比如 key 无效、网络不通）
3. 每轮结束会显示 `done` 信息：走了几步、花了多少 token、为什么停

### 几个值得试试的问题

```
读一下 README.md，用中文总结 Status 那一节
用 shell 跑一下 python --version，告诉我输出
在项目里搜一下哪个文件定义了 AgentLoop，说明它在干嘛
```

> 注意：agent 的工具被限制在**当前工作区**内，访问它的上级目录（比如 `../`）会被拒绝。这是设计如此，不是 bug。工作区默认是项目根目录，但也可以换 —— 见下一节。

### 换个目录干活：工作区

页面**顶栏右侧**有一个 `workspace` 输入框，它决定这一轮 agent 能在哪个目录里读写文件、执行命令。

| 你想做的事 | 怎么做 |
|---|---|
| 用默认目录（项目根） | 什么都不用填，页面加载时会自动填好 |
| 换成别的目录 | 在框里填**绝对 Windows 路径**（如 `D:\Projects\other-repo`），然后正常发消息 |
| 确认这一轮到底在哪个目录 | 第一条消息发出时，对话里会多出一行 `workspace · D:\...` |

几条必须知道的规则：

- **目录必须已经存在。** 填错路径不会自动创建，而是立刻弹红条 `workspace does not exist: ...`。
  这是**刻意**的 —— 如果自动建一个空目录，agent 就会在一个假的空目录里干活，而你以为它在改真项目。**"不报错但结果全错"是最贵的一类 bug**，所以这里选择报错。
- **必须写 Windows 路径。** `/d/repo` 这种 Git-Bash 写法会被拒绝并提示 `D:\repo` —— 因为 `ntpath` 会把 `/d/repo` 当成"盘符相对路径"，静默解析成 `D:\d\repo`，而且退出码还是 0。
- **刷新页面会回到默认值。** 这个值不做持久化，每次打开页面都是项目根目录。想固定用某个目录，走命令行更省事：`loca chat --workspace D:\some\repo`。
- **安全前提**：服务只监听 `127.0.0.1`，所以能填的路径都只在你自己的机器上。**千万不要把 `--host` 改成 `0.0.0.0`** —— 那等于把本机的**文件读写加 shell 执行**一起开放给同一网络里的任何人。

### 改坏了能撤回：检查点与撤销

页面顶栏右侧有一个 `session <id>` 小字，那是这轮对话在会话数据库里的编号。**每一次要改文件的工具调用（`write_file` / `edit_file`）真正执行之前**，loca 会先把目标文件的当前内容存一份快照，然后在对话里插一行：

```
⛁ checkpoint @ step 3 · notes.txt   [ ↩ undo from step 3 ]
```

点那个 **↩ undo**，确认一次，它就把「第 3 步**以及它之后全部**的文件改动」还原回去 —— 和命令行的 `loca rollback <session> <step>` 是同一套语义。这一步新建出来的文件会被**删掉**（"之前不存在"和"之前是空文件"是两件事）。

几条必须知道的规则：

| 规则 | 说明 |
|---|---|
| 撤销范围 | 撤销第 N 步**及其之后全部**，不是只撤销第 N 步 |
| 谁会被记快照 | 只有 `write_file` / `edit_file`。`shell` 能碰任何东西，为每条命令快照整个工作区不现实，所以**shell 改的东西撤不回来**（结果里会写明） |
| 超大文件 | 超过 2 MB 只记名字不存内容，撤销时会标成 `skipped` |
| 对话本身不回退 | 磁盘上的文件还原了，但上面的聊天记录仍然显示"已改过"。以文件为准 |
| 中途换过工作区 | 每个快照都记着自己是在哪个工作区拍的，撤销会**写回各自原来的目录**，不会串到你当前指的目录 |

**从命令行接手同一场对话**：顶栏那个 `session <id>` 直接复制进终端就可用：

```
loca sessions show 20260926-131621-a1b2c3     # 这轮对话的全文 + 检查点清单（step 号在这里看）
loca rollback 20260926-131621-a1b2c3 3        # 等于点页面上那个 ↩ undo
```

> 刷新页面会**新开一个会话**（对话内容、session id 都重置），但**旧会话和它的检查点还留在数据库里**，照样能用上面两条命令回滚。这也是为什么顶栏一直显示着那个 id。

### 聊长了会怎样：上下文压缩

上下文接近预算（默认 48,000 tokens）时，loca 会让模型把**较早的那些轮次压成一段摘要**，只保留最近 6 条原文 —— 和命令行是同一套策略，因为网页和命令行走的是同一份装配代码（`loca/agents.py` 的 `build_agent()`）。所以浏览器里聊久了，你会看到最前面变成一条 `[Earlier conversation summary]`，机制细节见 [`sessions-and-rollback.md`](sessions-and-rollback.md) 第六节。

| 事项 | 说明 |
|---|---|
| 库里存的是压缩后的版本 | 会话表存的是「模型实际看到的那份对话」，不是原始日志。压缩发生之后，被压掉的原文只剩下摘要了 —— 这是有意的，否则会话库会无限膨胀 |
| 参数不可调 | `--token-budget` / `--keep-recent` / `--no-summarize` 是命令行才有的开关，网页固定用默认值 |
| 网页不写执行轨迹 | `loca report` 需要的那份逐步轨迹（prompt 摘要 / token / 耗时）只在命令行入口产生。要在网页聊的场景下事后排查，用命令行起同一场对话 |

## 六、怎么关闭

### 方式 1：VS Code 调试面板（如果你是用 F5 启的）

- 按 **`Shift + F5`**，或
- 点调试工具栏上的 **红色方块 ⏹**，或
- 点终端面板右上角的 **垃圾桶图标**

### 方式 2：终端里按快捷键（如果你是终端启的，或用了上面方式1但没关掉）

1. 鼠标**点一下终端区域**（让它获得焦点，否则按键会发给编辑器）
2. 按 **`Ctrl + C`**
3. 看到终端出现类似这些行，就是正常退出了：

```
INFO:     Shutting down
INFO:     Waiting for application shutdown.
INFO:     Application shutdown complete.
INFO:     Finished server process [19748]
```

### 怎么确认真的关掉了

刷新浏览器页面，应该变成**"无法访问此网站 / 连接被拒绝"**，同时日志不再增加新行。

"连接被拒绝"这时候是好消息——说明窗口确实关了。

## 七、关不掉 / 端口被占用怎么办

这是你**最可能遇到的坑**：上次的服务没关干净，或者关了但进程没退，你又启动一次，就会报错：

```
ERROR:    [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8765):
          [winerror 10048] 通常每个套接字地址(协议/网络地址/端口)只允许使用一次。
```

翻译成人话：**门牌 8765 已经被别的进程占着了，我挂不上牌子。**

（`bind` = 绑定，`address` = 地址，`Errno 10048` 就是 Windows 的"端口已被占用"错误码。）

### 三步排查

#### 第 1 步：查出门牌被谁占了

在终端（cmd / PowerShell / VS Code 终端都行）敲：

```
netstat -ano | findstr :8765
```

**真实输出长这样**：

```
TCP    127.0.0.1:8765         0.0.0.0:0              LISTENING       8012
```

怎么读这行：

| 片段 | 含义 |
|---|---|
| `TCP` | 用的 TCP 协议（不用管） |
| `127.0.0.1:8765` | 本地这一头：就是被占的地址和端口 |
| `0.0.0.0:0` | 远端那一头，本地监听时这里是空的 |
| `LISTENING` | 状态："正在监听"= 就是它在占着 |
| `8012` | **最后一列是进程号 PID，等下要用** |

如果**这行什么都没有**，说明端口其实空着——那你的报错可能是别的原因（见下一节）。

#### 第 2 步：确认这个 PID 是不是 loca（可选但建议）

```
tasklist | findstr 8012
```

会看到类似 `python.exe    8012 Console    1    XXX K`。如果显示的是 `python.exe`，基本就是它。

#### 第 3 步：杀掉它

```
taskkill /F /PID 8012
```

把 `8012` 换成你上一步查到的数字。成功会输出"成功: 已终止 PID 为 8012 的进程"（有时中文会显示成乱码，不用管，能执行就行）。

再查一次确认：

```
netstat -ano | findstr :8765
```

这次没有任何输出，就说明端口释放了，可以重新启动。

#### 备选：用 PowerShell 一条命令搞定

```powershell
Get-NetTCPConnection -LocalPort 8765 | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

这行读作：查出所有用 8765 端口的连接 → 对每一个 → 停掉它所属的进程。

#### 备选：干脆换个端口

不想折腾杀进程，换个门牌就行：

```
.venv\Scripts\python.exe -m loca.cli serve --port 9000
```

然后浏览器开 `http://127.0.0.1:9000`。

> 用 VS Code 的 F5 启动的话，要改 `.vscode/launch.json` 里 `loca serve (Web GUI)` 那条的 `"args"`，把 `"8765"` 改成 `"9000"`。

## 八、命令行参数速查

| 参数 | 默认值 | 作用 |
|---|---|---|
| `--host` | `127.0.0.1` | 监听地址。**别改成 `0.0.0.0`**，等于把本机 shell 暴露给局域网 |
| `--port` | `8765` | 门牌号。被占就换一个 |
| `--reload` | 关 | 改了 Python 代码自动重启。**开发时好用，但会多起一个子进程，也可能让端口更难杀干净**，平时建议不开 |
| `--log-level` | `info` | 日志详细程度。嫌吵可以设 `warning` |

## 九、常见问题速查表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 终端报 `[Errno 10048] ... 只允许使用一次` | 端口被占用 | 见第七节，或 `--port` 换一个 |
| 浏览器显示"无法访问此网站" | 服务没启动，或已经关掉了 | 看终端是否有那四行启动日志；确认没按过 Ctrl+C |
| 敲 `loca serve` 提示"不是内部或外部命令" | 虚拟环境没激活，PATH 找不到 | 用 `.venv\Scripts\python.exe -m loca.cli serve` |
| 页面打开但一发消息就红字报错，提到 API key | `.env` 里的 key 没被读到 | 看 `/api/health` 的 `providers_with_keys` 是不是空数组 |
| 调试面板按 F5 没反应 / 输入框打不了字 | 选错了配置，或终端没获得焦点 | 确认下拉框选的是 `loca serve (Web GUI)`；点一下终端再输 |
| 页面里工具调用报"路径不在工作区内" | 路径沙箱拦截 | 正常行为，只让 agent 在当前工作区内活动 |
| 顶栏填了工作区，一发消息就报红字 | 目录不存在，或写成了 Git-Bash 路径 | 看红字内容：`does not exist` 就检查拼写、先在资源管理器里建好目录；提示 Git-Bash 就改成 `D:\...` |
| 换了工作区，agent 却还在读旧的目录 | 输入框没改动，或页面刷新后回到默认值了 | 看对话里有没有 `workspace · D:\...` 那一行；刷新会重置为默认值 |
| 没看到 `⛁ checkpoint` 那一行 | 这一轮没写文件（只读文件 / 只跑 shell 都不会有快照）；或者用的是加 `--no-save` 的 CLI | 让 agent 改一次文件就会出现；CLI 加 `--no-save` 时不落库也不做快照 |
| 点了 `↩ undo` 说 `nothing to undo` | 那个 step 及之后本来就没有检查点（都是读操作） | 看对话里 `⛁ checkpoint @ step N` 的 N 才是可用目标；或 `loca sessions show <id>` 看清单 |
| 撤销后 shell 改的东西还在 | `shell` 不在快照范围内（设计如此） | 结果里会写这句提示；需要能撤销就用 `write_file` / `edit_file` |
| 日志里出现 `404 Not Found` 的 `favicon.ico` | 旧版页面没配图标，浏览器自动去要 | 已修（页面内嵌了图标），还看到就强制刷新一下 `Ctrl+F5` |
| 关掉终端后页面就打不开了 | 服务是终端启动的，终端一关进程就死 | 这是正常行为，要一直用就别关那个终端 |

## 十、一页速查（贴在手边）

```bash
# 启动（VS Code：Ctrl+Shift+D → 选 loca serve (Web GUI) → F5）
.venv\Scripts\python.exe -m loca.cli serve

# 换端口启动
.venv\Scripts\python.exe -m loca.cli serve --port 9000

# 访问
#   界面   http://127.0.0.1:8765
#   体检   http://127.0.0.1:8765/api/health

# 关闭
#   终端里点一下，然后 Ctrl+C   （VS Code 调试中是 Shift+F5）

# 改坏了要撤回
#   页面里点 checkpoint 那行的 ↩ undo
#   或者复制顶栏的 session id 到终端：
loca sessions show <session>          # 看检查点清单（step 号）
loca rollback <session> <step>        # 撤销第 step 步及其之后

taskkill /F /PID <那个数字>        # 杀掉
```
